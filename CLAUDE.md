## Architecture Overview

### Stack
- **Frontend**: Next.js 16 (App Router) + React 19 + TypeScript
- **Backend**: Convex (serverless functions with auto-generated types)
- **Auth**: Clerk (JWT-based authentication)
- **UI**: Tailwind CSS v4 + Base UI + ReUI (shadcn pattern)
- **Styling Utilities**: Class Variance Authority (CVA) + clsx + tailwind-merge
- **Animations**: Motion (Framer Motion) for declarative animations and transitions
- **Forms**: React Hook Form + Zod for type-safe form validation
- **Date Handling**: date-fns for date formatting and calculations
- **Calendar**: react-day-picker (v9.x) via ReUI registry for date selection

### Authentication Flow

**Three-part integration:**

1. **Frontend Auth (Clerk)**: `proxy.ts` middleware protects all routes except `/` using `@clerk/nextjs/server`

2. **Backend Auth (Convex)**: `convex/auth.config.ts` validates Clerk JWT tokens using `CLERK_JWT_ISSUER_DOMAIN` environment variable

3. **User Sync (Webhooks)**: `convex/http.ts` receives Clerk webhooks at `/clerk-users-webhook`:
   - `user.created` / `user.updated` → calls `internal.users.upsertFromClerk`
   - `user.deleted` → calls `internal.users.deleteFromClerk`
   - Validates webhook signatures using Svix library with `CLERK_WEBHOOK_SECRET`

### Provider Hierarchy

Located in `components/providers.tsx`:
```
ClerkProvider (root)
└── ConvexProviderWithClerk
    ├── Convex client (NEXT_PUBLIC_CONVEX_URL)
    └── Auth integration (auto-passes JWT tokens)
```

The `ConvexProviderWithClerk` wrapper automatically synchronizes authentication state between Clerk and Convex.

### Data Model

**Schema** (`convex/schema.ts`):
- `users` table:
  - `name`: string (first + last name from Clerk)
  - `externalId`: string (Clerk user ID from JWT subject)
  - Index: `byExternalId` for fast lookups
- `messages` table (example/placeholder for future features):
  - `body`: string
  - `user`: string (Clerk user ID)
  - Note: Currently part of the initial setup but not actively used in the app
- `journalEntries` table:
  - `userId`: Id<"users"> (reference to users table)
  - `content`: string (journal entry text, 10-5000 chars)
  - `mood`: string (one of 8 mood categories: Happy, Sad, Anxious, Calm, Energetic, Tired, Angry, Peaceful)
  - `date`: string (ISO format YYYY-MM-DD)
  - `_creationTime`: number (auto-generated by Convex for sorting multiple entries per day)
  - Indexes:
    - `byUserAndDate`: [userId, date] - Primary access pattern for fetching entries by date
    - `byUserId`: [userId] - For month-range queries and analytics

**Key Helpers** (`convex/users.ts`):
- `getCurrentUser(ctx)`: Returns current user or null (exported)
- `getCurrentUserOrThrow(ctx)`: Returns current user or throws error (exported)
- `userByExternalId(ctx, externalId)`: Lookup user by Clerk ID using `byExternalId` index (private helper, used internally by above functions)

### Convex API Pattern

All Convex functions auto-generate TypeScript types in `convex/_generated/`:
- Public APIs:
  - `api.users.current` - Get current authenticated user
  - `api.messages.send` - Send message (requires auth, auto-associates with current user)
  - `api.journal.getEntriesByDate({ date })` - Fetch journal entries for specific date (YYYY-MM-DD)
  - `api.journal.getDatesWithEntries({ month })` - Get dates with entries for calendar indicators (YYYY-MM)
  - `api.journal.getAllEntries()` - Fetch all user entries (for future search/analytics)
  - `api.journal.createEntry({ date, mood, content })` - Create journal entry with validation
- Internal APIs:
  - `internal.users.upsertFromClerk` - Sync user from Clerk webhook
  - `internal.users.deleteFromClerk` - Delete user from Clerk webhook
- HTTP routes: `/clerk-users-webhook` endpoint

**Important**: Convex HTTP routes are hosted on the Convex deployment URL (e.g., `https://[your-deployment].convex.site/clerk-users-webhook`), not as Next.js `/api` routes. Configure the webhook URL in Clerk dashboard using your Convex deployment URL.

Use `useQuery` and `useMutation` from `convex/react` in components. Authentication tokens are automatically included via the provider setup.

**Development tip**: View schema changes, function logs, and database contents in the Convex Dashboard at your deployment URL.

### Important Patterns

1. **Client Components**: Use `"use client"` directive for components that need interactivity, hooks, or client-side context (providers, pages with state)

2. **Server Components**: Keep layouts and static pages as server components by default

3. **Convex Mutations**: Always use `internalMutation` for webhook handlers to prevent direct client access

4. **Error Handling**:
   - Use `getCurrentUserOrThrow()` when user must be authenticated
   - Use `getCurrentUser()` when null is acceptable
   - Webhook validation returns 400 on signature failure, 200 on success

5. **shadcn/ui Integration**: Uses custom registry at `https://reui.io/r/{name}.json` configured in `components.json`

6. **Form Handling**:
   - Use React Hook Form with Zod validation instead of useState for forms
   - Define Zod schemas for type-safe validation
   - Use `@hookform/resolvers/zod` to integrate with React Hook Form
   - Minimize useState usage following Convex best practices

7. **Mental Wellness Design Principles**:
   - **Therapeutic Language**: Use warm, supportive copy instead of clinical/directive language
   - **No Pressure**: Avoid prescriptive language ("should", "must") in favor of invitations ("when you're ready", "if you'd like")
   - **Validation as Support**: Error messages should encourage and guide, not criticize or command
   - **Visual Warmth**: Prefer amber/warm tones over stark colors, use gentle icons (Leaf vs AlertCircle for read-only states)
   - **Emotional Safety**: Label difficult emotions gently (e.g., "Frustrated" instead of "Angry") while maintaining authenticity
   - **Respect Silence**: Empty states acknowledge that "Some days speak louder in silence" rather than pressuring creation

### Journal Feature (Phases 1-4 Complete - Production Ready)

**Current Status**: Fully implemented journal feature with backend, all UI components, page integration, and production polish complete. The feature is live at `/journal` route.

**Backend Implementation** (`convex/journal.ts`):
- `getEntriesByDate({ date })` - Fetch entries for specific date using `byUserAndDate` index
- `getDatesWithEntries({ month })` - Get dates with entries for calendar indicators
- `createEntry({ date, mood, content })` - Create entry with server-side validation

**Data Model**:
- Stores journal entries with mood (8 categories), content (10-5000 chars), and date (YYYY-MM-DD)
- Uses compound index `byUserAndDate` for efficient queries
- Multiple entries per day supported, sorted by `_creationTime`

**Validation Rules**:
- Date cannot be in the future (uses timezone-tolerant validation allowing UTC+14 to journal for "today")
- Content: 10-5000 characters (trimmed)
- Mood: One of 8 valid categories (Happy, Sad, Anxious, Calm, Energetic, Tired, Frustrated, Peaceful)
- Supportive error messages ("Just a few more words to capture this moment" instead of "Entry must be at least 10 characters")

**Mood Categories**:
1. Happy - Sun icon (amber)
2. Sad - Cloud icon (blue)
3. Anxious - Zap icon (orange)
4. Calm - Waves icon (cyan)
5. Energetic - Sparkles icon (yellow)
6. Tired - Moon icon (indigo)
7. Frustrated - Flame icon (rose) - Note: displayed as "Frustrated" but stored as "Angry" for backward compatibility
8. Peaceful - Leaf icon (green)

**Access Control**:
- All functions require authentication via `getCurrentUserOrThrow`
- Entries are user-scoped (userId field)
- Past entries are read-only (enforced in UI, Phase 2)

**Implementation Notes**:
- Date stored as ISO string (YYYY-MM-DD) for simple comparison
- Uses Convex best practices: `.withIndex()` instead of `.filter()` where possible
- No pagination initially (can add if users create 100+ entries/day)
